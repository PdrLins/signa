Signa Creator Program

Influencers share their code; when someone they brought pays for Premium, they earn a share. This page is the plan for getting the back-end ready: what to build, in what order, and what we need to decide first. Brazil first (finance YouTube and Instagram), then Canada and the US.

Summary

  • Most of the plumbing exists. Every user already has an 8-character invite code (their account ID), sign-up records who invited whom (users.referred_by, referrals table), and free users already get +5 stocks per friend. A creator is a user with a creator record, a higher-value reward, and a dashboard.
  • The missing piece is Premium sales. Commission is a share of what subscribers pay, and Signa doesn't sell Premium yet. Inside the iOS app it must be Apple In-App Purchase, so the back-end needs to receive Apple's purchase, renewal and refund messages first (Phase 0). That needs the paid Apple Developer account.
  • Recommended rules: 25% of what Apple pays Signa (30% for top creators), for each subscriber's first 12 months; credit goes to the code used at sign-up; earnings wait 60 days (refund window), then are paid monthly once over a minimum. Pix in Brazil, Wise or PayPal elsewhere.
  • What can be built now, before Apple: creator accounts, vanity codes (NATHFINANCAS), attribution and a creator dashboard showing sign-ups and active users (Phase 1). Money tracking switches on when Premium sales exist.

For the creator

  • Gets a code (their invite code, or a vanity code like SIGNANATH) and optionally an Apple offer code for their audience.
  • Sees a dashboard: sign-ups, active users, paying subscribers, earnings pending / available / paid, by month.
  • Gets paid monthly with a statement.

For the person who signs up

  • Enters the code at sign-up (sign-up already requires an invite code).
  • Gets a welcome benefit: the existing +5 free stocks, and optionally a discount on the first Premium year through an Apple offer code (decision Q4).
  • Never sees the creator's earnings; nothing changes in the app for them.

Who gets credit

  • Sign-up code (main path). The code typed at sign-up decides. A creator code links the user to the creator for 12 months from their first payment. One creator per user, first code wins, never changed later (no "code switching").
  • Apple offer code (optional). A creator can also get an Apple custom offer code (for example 20% off the first year). Apple reports which offer was used on the purchase, so Signa can credit the creator even if the person signed up with another code. Rule: the sign-up code wins when both exist.
  • Link to the right user. When the app starts a purchase it sends Apple an appAccountToken set to the Signa user's id; every Apple message about that subscription carries it back, so the payment maps to the user, and the user to the creator.
  • No credit: the creator's own subscription, users who sign up with a code after already having an account, payments after month 12, family-shared or refunded payments.

Jobs

  • Daily: move commission entries past their 60-day hold to available; end attributions after 12 months.
  • Monthly (1st): build each creator's statement and the payouts list for the owner.
  • Monthly (after Apple's report): compare Signa's records with Apple's financial report; flag differences.

Access: creators are a role on top of the plan (a Free or Premium user can be a creator), so the creator area checks the creators row, not the access level. The dashboard can live on the web app first (creators work on desktop), then in iOS.

Fraud and refunds

  • Refunds: Apple's refund message reverses the entry. Inside the hold, nothing was paid. After a payout, the amount is subtracted from the next one.
  • Self-referral: no commission on the creator's own subscription or accounts sharing their device or payment details (Apple doesn't share payment details; same device or same email domain patterns get flagged for review).
  • Fake sign-ups: attribution alone pays nothing; only real Apple payments do, so fake accounts can't earn.
  • Code leaks / coupon sites: codes can be paused; each code has a campaign label to see where users come from.
  • Audit trail: every entry keeps the Apple transaction id and the signed message, so any statement line can be traced.

Legal and Apple rules

  • Creator agreement (simple terms): rate, duration, hold, payout, refunds, that Signa can end the program, and conduct rules below.
  • Disclosure: creators must label the content as a paid partnership: CONAR guidelines in Brazil, Ad Standards in Canada, FTC rules in the US.
  • No investment advice: creators promote the app (tracking, dividends, calendar), never "Signa tells you what to buy" and no promised returns. Signa itself gives no advice, which keeps this simple.
  • Apple: Premium inside the app is sold only through In-App Purchase; paying creators outside the app is allowed. Signa can't reward users with money for subscribing. Offer codes follow Apple's limits per quarter.

Decisions we need

Who receives Apple's money? Your Canadian company (or sole proprietorship), or a Brazilian one later. This decides payouts and tax paperwork. Ask an accountant once, before Phase 4.
Rate and duration: 25% (30% top), first 12 months, on what Apple pays Signa. Or lifetime of the subscriber, or a flat amount per new subscriber.
Hold and payout: 60-day hold, monthly on the 5th, minimum R$100 / CA$25 / US$20.
Audience benefit: does the creator's audience get a discount (Apple offer code, e.g. 20% off the first year), or only the free +5 stocks? A discount helps conversion but lowers both Signa's and the creator's share.
Who can join: invite only, approved by you, or an open application form.
Creator dashboard: web page first (creators work on desktop), or inside the iOS app.
Start Phase 1 now? It works without Apple: you can onboard the first creators and watch sign-ups before Premium sales open.
