# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Signa back-end: a portfolio tracker (Free + Premium) for the web app and the iOS app (`~/Documents/projects/signa-ios`). No AI anywhere. The brain (scans, signals, AI checks, positions, learning, backtest) lives in **Signa Advisor** (`~/Documents/projects/signa-advisor`, a fork of this repo that merges `main` from here); don't add brain code back (`tests/test_signa_scope.py` guards it). Shared market helpers live in `app/market/` (known symbols, symbol resolution, technical checks in plain pandas, fund data, earnings dates).

## Commands

```bash
source venv/bin/activate
python -m uvicorn main:app --reload --port 8000
pytest tests/ -q                             # all tests
pytest tests/test_stock_page.py::test_name -v    # single test
```

## Environment

Config in `app/core/config.py` (Pydantic Settings from `.env`, unknown keys ignored). Required: `JWT_SECRET_KEY`, `SUPABASE_URL`, `SUPABASE_KEY`. Auth is always enabled. Validation at import time. One process only: APScheduler runs in-process, two instances would run every job twice.

## Worldwide (markets: Brazil, Canada, US first; any country works)

- **Currency per listing:** `app/market/currency.py` (suffix → currency/exchange: .SA BRL/B3, .L GBP/LSE (pence ÷100), .DE EUR/XETRA ...; no suffix = USD). Quotes store that currency.
- **Any-currency FX:** `price_cache.usd_rates` / `fx_convert` (Yahoo `{CCY}=X`, cached 1 h); `portfolio_snapshots.convert` routes every pair through USD (CAD always with the request's `usdcad`, so one response is consistent). Responses keep the old `*_cad` fields and add `*_home` (user's home currency): `/holdings` totals + position, `/dividends/calendar` Money/events/positions/summary. Tests stub FX (`conftest._no_live_fx`).
- **Search / resolution:** every exchange (German regional copies and OTC rank last), the user's country first (`COUNTRY_LABELS`, `HOME_BOOST`). Bare tickers: B3 pattern (PETR4) → `.SA` anywhere; else the country's suffix first (`market/symbols.COUNTRY_SUFFIX`).
- **Sessions:** `app/market/sessions.py` (exchange_calendars): the quotes job runs every minute and refreshes each symbol while its exchange is open (+10 min after the close); `market_calendar` uses it for non-NYSE/TSX holidays and bar completion.
- **Sign-up:** `POST /auth/register` takes `country`, `home_currency`, `language`, `locale` (`profile_service.signup_settings`). Telegram/push money is locale-formatted (`telegram_notify.money`, "R$ 1.234,56" for pt).

## Access levels

Users have `access_level` free | premium | owner (migration 011, read from the DB per request, cached 60s). Every area (page) and action (button) is a feature key with a minimum level: defaults in `app/core/access.py`, overridden by the `access_features` table. Routes declare `Depends(require_feature("..."))`; `tests/test_access.py` fails if a new route has neither a feature nor an entry in its UNGATED list. `access_features` rows for keys not in the catalog are ignored. Clients (web, iOS) read `GET /auth/me` for level, allowed keys, catalog and slots; 403 bodies carry `{"code": "upgrade_required" | "slot_limit" | "alert_limit"}`, the two limit codes with `"upgrade": {"feature", "plan": "premium"}` so clients open the upgrade screen. **Followed symbols are what users pay for:** free follows 15 + 5 per rewarded referral (max +25, migration 019; `users.slot_bonus` is kept but ignored), premium and owner unlimited (`system.unlimited_slots` = premium, migration 015). `access.slot_limit` is the only place the limit is computed (`slots.limit_for` feeds it the rewarded count for `/auth/me` and every 403). Price alerts: free 3 active, premium/owner unlimited (`feature.unlimited_alerts`).

## Sessions (migration 017, iOS sign-in plan A)

Every sign-in creates an `auth_sessions` row (one per device; `client` web|ios, `device_name`). Access JWTs carry `sid` + `cli`; the auth middleware rejects a token whose session is revoked/expired (`sessions.is_active`, cached `session_check_cache_seconds`, fails open on DB errors). Login/verify-otp accept `client` + `device_name`. **iOS:** 15-min access token + opaque refresh token (only its SHA-256 in `auth_refresh_tokens`), `POST /auth/token/refresh` rotates it; a used token presented again revokes the session (`reuse_detected`) — except an idempotent retry: the new token is derived from the old (`sessions.successor_token`, HMAC), so re-presenting the token rotated < `session_refresh_grace_seconds` (30) ago while its successor is unused returns the same new refresh token once; sliding 90 days, absolute 180, owner 30. **Web:** no refresh token yet, keeps `/auth/refresh` (access-token refresh, 24 h cap) with `sid` carried over. `GET /auth/sessions`, `DELETE /auth/sessions/{id}`, `POST /auth/sessions/revoke-others`; logout revokes the session. Before 017: sign-in works without sessions, the new routes answer 503 migration_required. Service: `app/services/sessions.py`; tests `tests/test_sessions.py`.

## Referrals and invite-only sign-up (migration 019)

Every user has a visible 8-char `users.account_id` (alphabet `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, upper-cased on input) that is also their invite code; it is in `GET /auth/me` and `/profile` (null before 019). `POST /auth/register` (public, AUTH rate-limit tier counting every attempt, audited `USER_REGISTERED`/`REGISTER_FAILED`) takes `username`, `password`, `referral_code` + `client`/`device_name` and returns 201 with the password-only login payload (tokens from `auth_service._issue_access_token`); errors 422 `invalid_referral` | `invalid_username` (3–30 `[a-z0-9_.]`, stored lower-case) | `weak_password` (< 8 chars or > 72 bytes), 409 `username_taken`. It creates a free user (no Telegram, bcrypt like `create_user.py`), `users.referred_by` and a `referrals` row (pending). `GET /auth/referral/{code}` (public, 20/15 min per IP) → `{"valid"}`. `GET /referrals` (area.profile) → code, share_url (`WEB_APP_URL` + `/signup?code=`), per_friend 5, max_bonus 25, bonus_slots, invited/rewarded/pending, unlimited. The invited user's first holdings save or watchlist add marks the referral rewarded (conditional update on `status='pending'`, once) and, when the referrer has a linked Telegram notification chat + `feature.telegram_alerts`, sends them "Your friend joined Signa — +5 stocks" in the background. `create_user.py --referral CODE` records a referral the same way. Before 019 the three routes answer 503 migration_required; nothing else changes. Services: `referrals.py`, `registration.py`; tests `tests/test_referrals.py` (fakes `tests/referral_fakes.py`; conftest stubs the referrals DB as "no 019" by default).

## Two-step sign-in (migration 020)

Optional per user, Telegram now (SMS listed, no provider). Setup proves the chat: `POST /auth/2fa/telegram/start` → one-time link `t.me/<bot>?start=2fa_<code>` (or `use_connected_chat` = the 016 notification chat) → the bot sends a 6-digit code → `POST /auth/2fa/telegram/confirm` sets `users.telegram_chat_id` + `two_factor_method='telegram'`. Login asks for the code only when `two_factor.is_enabled(user)`. Owner can't disable. Bot messages arrive by webhook or, locally, by polling `getUpdates` (`app/notifications/telegram_updates.py`, `TELEGRAM_POLLING`). Service `app/services/two_factor.py`, routes `app/api/v1/two_factor.py`.

## Prices outside the session (migration 021)

`quotes_offhours` job every minute: crypto (`-USD`) refreshed 24/7 at plan rates (free 15 min, premium 1 min); US stocks (no suffix) followed by Premium get pre-market (4:00–9:30 ET) / after-hours (16:00–20:00 ET) prices in `quotes.ext_*` every `quotes_refresh_seconds_extended`. `feature.extended_hours` = premium. `/portfolio/summary` has `market_phase`, `extended` {session, abs, pct, as_of, symbols}, `extended_locked` (free hint); `/stocks/{symbol}` quote and `/watchlist/overview` rows have `extended` + `extended_locked`; Premium 1D history includes pre/post bars and `session` {open, close}. Shown only while newer than the regular price and outside the session (`quotes.extended_view`).

## Portfolio tracker (MVP)

Global, free tracker (migration 013; no AI anywhere in it). Web and iOS use the same endpoints; every docstring has the response shape; errors are `{"detail": {"code", "message", ...}}`. Before 013 the new endpoints answer 503 `migration_required` (`app/core/api_errors.run_db`), `/holdings` keeps working (`account_id` null) and the jobs no-op.

- **Tables:** `user_settings` + display_name, country (ISO alpha-2), home_currency (CAD), dividend_tax_view, compare_index (NULL = no benchmark), holdings_native_currency, allocation_targets; `portfolio_people`; `accounts` (user-created and user-named — no defaults; optional `account_type`); `holdings.account_id` (unique on user + COALESCE(account_id) + symbol, so one stock can sit in several accounts; old `account` column deprecated, not written); `transactions`; `quotes` (shared); `portfolio_snapshots`; `notification_prefs`.
- **Endpoints:** `GET/PUT /profile` (+ `/profile/options`) and `GET/PUT /notifications/prefs` (area.profile); `/people` and `/accounts` CRUD (reads area.holdings, writes action.accounts.edit; deleting an account with holdings → 409 unless `?move_to=` or `?force=true`, same-symbol lots are merged); `/holdings` items carry account_id/account_name, `?account_id=`/`?person_id=` filters, upsert keyed on (account_id, symbol); `/transactions` CRUD (action.transactions.edit), `/transactions/template` + `/transactions/import` (multipart, `dry_run` default true, `create_missing_accounts`, `skip_errors`, `date_format`) + `DELETE /transactions/import/{batch_id}` (action.import.csv).
- **Rules:** account type needs `action.accounts.type` (free since migration 022; 403 if a DB override locks it) and country CA/US with a type of that country (422). `dividend_tax_view="after"` needs `feature.tax_view` (premium) + CA/US; reads return the effective value. Transaction `amount` is always positive (direction = type); split `quantity` = ratio. CSV: Signa's template `date,type,symbol,quantity,price,amount,currency,fee,account` (+note), account by name, ≤ 5,000 rows / 2 MB. Slots stay per distinct symbol (holdings + watchlist).
- **Insights (migration 014; all AI-free, scope `?account_id=`/`?person_id=` via `portfolio_context.load_scope` → 404 account_not_found/person_not_found, 422 invalid_scope; every price-bearing response has `as_of` + `delayed_minutes: 15`):**
  - `GET /portfolio/summary` (area.home): market_value, cash, total, day_change, total_gain (unrealized + realized + dividends when transactions exist), holdings_count, estimated flags. `GET /portfolio/history?range=1D|1W|1M|3M|YTD|1Y|5Y|ALL&compare=` (area.home): `{t,value}` series; 1D = intraday bars (5m with `feature.intraday_chart`, else 15m; per-symbol cache 3 min); longer = `portfolio_snapshots`, else estimated from current shares × daily closes (`estimated`, `estimated_reason`); ALL needs `feature.full_history` (403). `compare` only when passed (benchmarks of `/profile/options`), scaled to the start value. `GET /portfolio/performance` (area.insights): modified Dietz when transactions exist (flows = deposits/withdrawals, else trades), else "estimate"; drivers in points of return; vs benchmark with compare. Service: `portfolio_performance.py`.
  - `GET /dividends/summary?period=next12m|YYYY` (area.dividends): expected (profiles) or received (ledger), 12 monthly bars steady vs variable, yield, yield on cost, growth 5y/1y, payers (safety growing|steady|variable|watch|cut, 12-month pattern), upcoming 60 days, "why your income changed" vs `income_forecast_snapshots` (~30 days; `available_from` until history exists). After-tax (feature.tax_view + CA/US + view "after") via `dividend_tax.py` rules (CA: US dividends lost in TFSA/FHSA/RESP, 0% RRSP, recoverable NON_REGISTERED; `inside_fund` for Canadian ETFs holding US stocks; US: CA dividends recoverable only in TAXABLE; untyped accounts untaxed, listed). `GET /portfolio/income-quality/{symbol}` (area.insights + `feature.income_quality`, premium since migration 022): class steady|option_income|cash_like, yield source, 12-month payouts, 5y total return vs a documented underlying map.
  - `GET /events/upcoming?days=30` (area.coming_up): merged feed of ex_dividend, dividend_payment, earnings (avg abs move over 8 reports), check_changed (`check_status_daily`), analyst (last 7 days, held only), economy (`economic_calendar.py`, MANUALLY maintained BoC/Fed/CPI dates 2026–2027); `sources` block per source.
  - `GET /portfolio/allocation` (area.insights): mix by class (stocks, broad_etfs, option_income_etfs, cash_like incl. account cash, crypto, other), tiles, warnings (top3 > 40%, single > 20%, cash_like > 10%, option_income > 25%); `GET/PUT /portfolio/allocation/targets` (sum 100) and `GET /portfolio/allocation/plan?amount=` need `feature.allocation_plan` (premium since migration 022; the mix stays free); (under-target classes only, no selling; 409 no_targets).
  - **Live prices everywhere:** `/holdings` items are priced with the shared `quotes` table (same as `/portfolio/summary`; fallback holding_status = `price_source: "last_close"` with null day change) and carry `quote` {price, prev_close, change_pct, change, as_of, live, price_source, ytd_pct_live}; `position.symbol_weight_pct` (symbol across accounts) drives `overweight`; `totals.as_of`. Summary `day_change` counts live quotes only. `/stocks/{symbol}` overlays the header quote with a newer `quotes` row and adds `fund` (ETFs, `market/funds.build_fund_info`, ~12h cache, 8s cap), `about`, dividend `growth_{1,3,5,10}y_pct`. `/watchlist/overview` suggestions carry price/change_pct/currency (`following.suggestion_quotes`, 15-min cache).
  - **Stock page (015):** `GET /stocks/{symbol}` adds shared `statistics` (day range, 52w, market cap, P/E, forward P/E, dividend_yield FRACTION, volumes, beta) and per-user (never cached) `position` (null when not held; shares/weighted avg cost across accounts, market value + home, weight_pct, today/open P/L, dividends_received + realized from the ledger, total_gain, per_account) and `slots`.
  - **Price alerts (migration 015, `services/price_alerts.py`):** `/alerts` GET (area.stock, `?symbol=`) / POST / PATCH / DELETE (action.alerts.edit); above = price >= target, below = price <= target, USD/CAD converted, never fired when unconvertible; creating one already crossed → 422 already_crossed. The quotes job treats active-alert symbols as followed and, after storing quotes, fires crossed alerts once (triggered_at + last_price, active=false). Fired alerts of the last 7 days appear in `/events/upcoming` as recent `price_alert` items (whole-portfolio scope). Push delivery: later.
  - `GET /admin/usage?days=30` (area.admin, owner): `data_usage_daily` counters (provider calls, symbols refreshed, heavy-endpoint requests; `usage_metrics.record` buffered, flushed every 5 min).
- **Cost control (014):** quotes job runs every minute but refreshes a symbol only when due for its best active follower (premium/owner every `quotes_refresh_seconds_premium` 60s, free-only every `quotes_refresh_seconds_free` 900s), only for users seen in the last `quotes_active_user_days` (7; `users.last_seen_at`, written ≤ hourly by the auth middleware, fallback `last_login`); 16:05 refresh covers all. `quotes.as_of` is the real price time (`as_of_source` bar|fetch|close). Jobs: income forecast 18:00 ET, check statuses 18:15 ET (`portfolio_insights_jobs_enabled`). Holding status (`services/holding_status.py`, 17:45 ET weekdays and right after a user adds holdings): one batched download, writes `holdings.holding_status` (price fallback, YTD base); no AI, no alerts.
- **Services:** `portfolio_ledger.derive_positions` (pure average-cost: shares, avg cost, realized P/L, dividends per year, cash per account) for later phases; `quotes.py` (one batched yfinance download, `quotes` table; job every 60s in the 09:30–16:00 ET session + 16:05 after close); `portfolio_snapshots.py` (16:30 ET weekdays, per user and per account in home currency; only USD/CAD convert, others listed as `unconverted`).
